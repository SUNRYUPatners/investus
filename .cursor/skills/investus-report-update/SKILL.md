# Investus 리포트 업데이트 스킬

리포트 날짜 세트를 추가할 때 **항상** 이 스킬 + `.claude/commands/report-update.md` 전체 순서를 따른다.

## 서브에이전트 — 리포트 업데이트 시 Opus 5 사용 (2026-08-27~)

리포트 업데이트(`리포트 업데이트`, `report-update`, 일일 seed·SVG·본문 배치)는 **Task 서브에이전트**를 **`claude-opus-5-thinking-high`(Opus 5)** 로 실행한다. `lib/reports.ts` 본문 풍성화·한글 SVG·다시장(kr/safe/kr-re) 일괄 작성처럼 **분량이 큰 작업**은 부모 에이전트가 전부 직접 쓰지 말고 Opus 5 서브에이전트에 위임한다. 단순 팩트 수정·시드 1~2개만 고치는 경우는 예외.

## 문장으로 쓰기 · 존댓말 — 제목·부제·본문 (2026-08-25부터 필수)

> 피드백 1: 제목·부제·본문이 **단어 나열**이라 초보자가 못 읽는다. 문장으로 풀어서 풍성하게 쓴다.
> 피드백 2: 리포트 말투가 **반말**이다. 공식 리포트는 **존댓말(합니다체)** 로 쓴다.

**적용 범위 (존댓말 + 문장):** `title` / `summary` / `body` / SVG 한글(`title`·`heroSub`·quote·noteSub·카드 설명) / 한장요약 제목·요약. 영문(`titleEn` 등)은 평서문 문장.

**출처 이름은 쓰지 않습니다 (2026-08-25~)**
- 독자에게는 **내용만** 씁니다. 스크린샷·소셜 핸들·매체 바이라인은 카피에 넣지 않습니다.
- **금지 예:** `Cosmos Europa`, `DogeDesigner`, `Robotaxi Radar`, `Doctor Jack`, `Shay Boloor`, `Joe Hansen`, `Sam Badawi`, `Evan`, `Sawyer Merritt`, `Barchart`, `Bull Theory`, `(출처 Company reports, Deutsche Bank Research)` 를 heroSub·카드 `sub`·quote·본문 첫머리에 반복.
- 나쁜 예: `Cosmos Europa: F14가 F13보다 어렵다` / 카드 하단 `Cosmos Europa` / `"Cosmos Europa는 Flight 14가 13보다 어렵다고 했다."`
- 좋은 예: `스타십 14번째 비행은 13번째보다 어렵습니다. 41호기는 초속 약 7.8km로 궤도에 들어간 뒤 한 바퀴를 돌고 다시 대기권으로 들어오며, 연료를 남깁니다.`
- **예외:** 그 매체·인물의 발언 자체가 뉴스인 경우만 (예: 워런 버핏 인터뷰, 머스크 본인 발언). 그래도 같은 이름을 제목·카드·인용에 세 번 반복하지 말고, 카드 `sub`에 출처 라벨을 달지 않습니다.
- 팩트체크는 내부에서 스크린샷과 숫자를 대조합니다. 출처를 지웠다고 숫자를 지어내지 않습니다.

**예외 — 반말·구어체 유지:** `lib/wallPosts.ts` 종토방만. 익명 게시판 캐릭터이므로 구어체를 유지한다. 애널리스트 글(`analystPosts.ts`)도 공식 해설에 가깝게 **존댓말**로 쓴다 (캐주얼 이모티콘·반말 금지. 구조 다양화 규칙은 유지). 애널도 계정명 나열은 하지 않고 내용만 씁니다.

**한글판 애널 — 영문 키워드 나열 금지 (2026-08-27)**
- 나쁜 예: `Terafab Texas +$48B, total $119B… build window입니다.` / `today bundle: NVDA beat/AH -2%…`
- 좋은 예: `텍사스 테라팹 추가 투자 480억 달러가 더해지며 총 규모가 약 1,190억 달러로 잡혔습니다.`
- 영문 `titleEn`/`bodyEn`이 필요한 리포트와 달리, **한글 UI 애널 카드(`content`)는 한국어 문장**이 본문이다.

**말투 (합니다체)**
- 종결: `~습니다` / `~입니다` / `~합니다` / `~했습니다` / `~됩니다`. 인용문 속 원문만 반말 허용.
- **금지:** `~다` / `~이다` / `~한다` / `~인가` / `~봐야지` / `~임` / `~네` 등 반말·음슴체·체언 종결.
- 제목도 가능하면 합니다체. 너무 길면 `~합니다`로 끝나는 한 문장. 예: `테슬라가 … 행사를 엽니다`

**금지 (나쁜 예)**
- 제목: `Tesla Cybercab 전용 이벤트 09.03.26 Austin TX · Exclusive Access`
- 반말: `테슬라가 오스틴에서 사이버캡 행사를 연다`
- 요약: `Austin에 4680용 북미 첫 대형 캐소드. 중국 공급 ~90%·2025 수출통제.`
- 본문: `1. 허가다. 2. 원가다.` / `수율 안정`

**권장 (좋은 예)**
- 제목: `테슬라가 운전석 없는 전용 로보택시(사이버캡) 공개 행사를 9월 3일 오스틴에서 엽니다`
- 요약: `테슬라가 운전석을 없앤 전용 로보택시 사이버캡 행사를 2026년 9월 3일 텍사스 오스틴에서 연다고 알렸습니다. 기존 모델Y에 소프트웨어만 얹은 차가 아니라, 처음부터 무인 운행용으로 만든 차량입니다. 날짜가 정해지면 상용 일정이 말에서 달력으로 내려온 것입니다.`
- 시나리오 한 줄: `수율이 안정되면 북미에서 배터리 셀을 더 싸게 만들 수 있어, 로보택시 한 대 원가 논쟁이 누그러질 수 있습니다.`

**제목·부제 규칙**
- 주어+동사가 있는 **한글 존댓말 문장**. 영문 제목도 완전한 절. 티커는 필요하면 `테슬라(TSLA)`처럼 한 번만.
- `·`로 고유명사·숫자를 5개 이상 나열하지 말 것. 숫자는 문장 속에 (`약 87%`, `981억 달러`).
- `subject`(카드 작은 라벨): **종목분석은 종목 한글명만** (`테슬라`, `스페이스X`, `엔비디아`). `Citizens IRR` 같은 토픽 슬러그 금지. 특집은 `한장요약`, 매크로는 `금리` 등 짧은 분류.
- SVG `heroSub`는 **2문장 안팎, 합니다체**.

**본문 풍성함 (짧게 쓰고 끝내지 말 것)**
- 분량 기준은 **2026-08-18 seed-994급**이되, **존댓말 설명 문단**으로 채운다. 섹션당 불릿 5개로 때우지 말 것.
- 초보 독자: 용어마다 **한 문장 정의** (`캐소드는 배터리의 양극재입니다`).
- `■ 상세`는 배경·비교·한계를 문단으로 이어 씁니다.
- `■ 왜 이 뉴스가 중요한가`는 번호마다 **2~4문장, 합니다체**.
- `■ 투자시사점`은 무엇을 추적하면 되는지를 3문단 이상, 존댓말로.

**자가 점검 (배포 전)**
- 제목이 고유명사 나열인가? → 문장으로.
- 한글 본문에 `다.` / `이다.` / `한다.` / `임.` 으로 끝나나? → 합니다체로.
- **한글 `title`/`summary`/`body`에 영문 키워드 덤프(`supply fear`, `BTC ~78128`, `**A hold**` 등)가 섞였는가? → 전부 한국어 문장으로. **`public/charts/*-YYYYMMDD.svg`(한글판, `-en` 제외) caption·heroSub도 동일.** 배포 전 `node scripts/validate-report-korean.js` 통과 필수.
- 카드·인용·hero에 소셜/매체 출처 이름이 보이나? → 지우고 내용만.
- 약어를 설명 없이 쓰는가? → 풀이 추가.
- body가 한 화면에 다 들어오나? → 문단 보강.

### SVG 카피 밀도 — 초보자도 이미지만으로 이해 (2026-08-22부터 · **다음날 생성분부터 적용**)

> 반려/피드백: 인용 박스 1문장 + 「왜 중요한가」 2줄만 있으면 처음 보는 사람이 용어·의미를 못 잡음 (예: Cybercab / 유닛 이코노믹스 / NTA 발언만 단정).

**중간 인용(quote) 박스**
- 단순 헤드라인 복붙 금지. **무슨 일이 있었는지 + 숫자·범위 1개**를 2~4줄로. **출처 계정/매체 이름은 넣지 말 것.**
- 전문 용어가 나오면 바로 옆에 짧은 풀이 한 절 (예: 「Cybercab = 운전석 없는 전용 로보택시 차량」).
- KO 기준 대략 **80~140자 / 2~4줄**을 목표. 한 줄짜리 인용만 두지 말 것.

**하단 「왜 중요한가」/ noteHead·noteSub (또는 의미 박스)**
- noteHead만 쓰지 말고 **noteSub에 초보용 설명 2~3문장**을 반드시 채운다.
- 구조 권장: (1) 이게 왜 뉴스인가 한 줄 → (2) 기존과 뭐가 다른지 / 비교 대상 → (3) 다음에 볼 포인트 한 줄.
- 전문 용어(유닛 이코노믹스, 허가, lockup, D2D 등)는 **비유·한 줄 정의**로 풀기.
- KO 기준 noteSub **약 100~180자 / 2~3줄** — 카드 3개에 이미 쓴 키워드만 반복하지 말 것.

**KPI/피처 카드 3칸**
- `big`은 짧아도 됨. `mid`·`sub`에는 **초보가 맥락 잡는 보조 설명**을 넣기 (지명·기간·비교 대상).

**레이아웃 여유**
- 글이 늘면 quote/note 박스 높이·`multilineIfOverflow` maxLines를 **먼저 늘리고** 잘라내지 말 것 (SVG Read로 점검).
- 「투자 시사점」 라벨은 여전히 SVG에 금지 — 설명은 자연 문장으로만.

### SVG 밀도 — 2026-08-28부터 강제 (8/27 부실 반려)

## 본문(body) 원칙

1. **본문(`lib/reports.ts` body/bodyEn)에는 상세 설명·배경·출처·투자시사점을 충분히 채운다.** 분량은 **2026-08-18 리포트(seed-994 등) 수준의 한글 서술**을 기준으로 한다 — 짧게 끊은 영문 불릿 아웃라인 금지. **2026-08-25부터는 그 분량을 ‘키워드 압축’이 아니라 초보용 **존댓말 문장**으로 채운다** (위 「문장으로 쓰기 · 존댓말」).
2. 권장 구조(한글 **완결 문장**): `■ 상세` → `■ 왜 이 뉴스가 중요한가` → (시나리오/경쟁 구도) → `■ 오늘까지 흐름` → **`■ 장기 투자 관점`** → `■ 앞으로 볼 것` → `■ 투자시사점`. 의미·향후 전망·시나리오를 서술로 풀어쓴다.
3. **`■ 반대 관점` 금지 (2026-08-30~)** — 단기 반론·리스크 불릿 `(1)… (2)…` 나열은 쓰지 않습니다. 대신 **`■ 장기 투자 관점`** 에서 장기 투자자 시각으로 풀어 씁니다:
   - **과거→미래 서사**: 이 테마·종목·산업이 **지금까지 어떻게 왔는지**를 2~3문장으로 짚고, 그 흐름이 **앞으로 3~5년(또는 그 이상) 뷰에서 어떻게 이어질지**를 연결합니다.
   - **장기적으로 좋은 점**: 단기 노이즈·일시적 악재와 구분해, **인내 투자자에게 유리한 구조·해자·추세**가 무엇인지 문단으로 설명합니다.
   - **톤**: 회의적 반론 나열이 아니라 「역사적으로 ~해 왔고, 이번 뉴스는 그 긴 그림에서 ~한 조각입니다」 식의 **서술형**입니다.
   - **금지 예:** `(1) 발표와 상업 가동은 다릅니다 (2) 중국 의존 리스크…` — 번호만 바꾼 반대 의견 리스트.
   - **좋은 예:** `로보택시는 2016년부터 ‘언젠가’라는 내러티브만 있었습니다. 이번처럼 날짜·차량·도로 데이터가 겹치는 구간은, 단기 주가 변동과 별개로 5년 뷰에서 실행 리스크가 줄어드는 구간으로 기록될 수 있습니다.`
4. **금지**: `■ 배경 / 관련 보도 (상세)` 아래 영문 메모형 불릿(`Exact prints…`, `Align with…` 등). 관련 보도는 한글 문장 속에 출처를 녹여 쓴다. **제목·요약을 `A · B · C` 헤드라인 체인으로 쓰는 것도 금지.**
5. 모든 개별 리포트에 `■ 투자시사점` (EN: `■ Investment Implications` 또는 Aug 18처럼 `bodyEn: "See Korean body.…"`) 필수 — SVG 안에는 라벨 없이 자연스럽게 녹여도, 본문에는 항상 명시적 섹션으로 있어야 함.

**8/28 강제: body 영문 불릿 금지** — `■ 오늘까지 흐름`/`■ 장기 투자 관점`/`■ 앞으로 볼 것`에 영어 단어 나열 1줄 금지. 각 항목 완전한 한글 문장. 배포 전 grep으로 `[a-z]{4,}` 영문 연속 3개 이상 bullet 검사.
