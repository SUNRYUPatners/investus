#### 팩트체크 의무 절차 (순서대로 전부 실행)

**Step 1 — 핵심 수치 목록 추출**
작성한 모든 리포트에서 아래 항목을 표로 정리한다:
| 리포트명 | 수치/가격/% | 출처 스크린샷 파일명 |
|---------|------------|-------------------|
| (예) SPCX RJ PT | $800 | 스크린샷 7:37:36.png |

**Step 2 — 스크린샷 원본 재독 (Read tool 사용 필수)**
위 표의 각 항목마다 해당 스크린샷 파일을 `Read` tool로 **실제로 다시 열어서** 숫자를 직접 눈으로 확인한다.
- 기억에 의존하거나 "아까 봤으니까 맞겠지" 하는 추론 절대 금지
- 스크린샷 글씨가 작아서 불명확하면 불명확하다고 명시하고 가장 보수적인 숫자 사용

**Step 3 — 1:1 대조 체크리스트**
- [ ] 가격·목표주가 → 스크린샷 원문 숫자와 정확히 일치
- [ ] 퍼센트(%) → 방향(+/-)과 수치 모두 일치
- [ ] 날짜 → 원문 날짜와 일치
- [ ] 회사명·종목·사람 이름 → 오탈자 없음
- [ ] 방향성(상승/하락, 매수/매도) → 원문과 동일
- [ ] 없는 사실 창작 여부 → 스크린샷에 없는 내용 0건

**Step 4 — 불일치 발견 시**
즉시 수정 → 해당 SVG·ts 파일 수정 → 스크린샷 재확인 → 체크리스트 재통과

## 중요 규칙
- 1 리포트 = 1 주제 — 하나의 seed에 여러 주제 섞지 않는다
- **같은 종목이라도 이벤트/주제가 다르면 반드시 별도 리포트로 분리** — 한 seed에 독립적인 여러 이벤트 묶지 않는다 (예: 한국 FSD 구독 개시와 스페인 FSD 승인은 별도 seed)
- 날짜별 타임스탬프는 상대 오프셋으로 계산 (`_now - N*3600_000`)
- 배포 전 TypeScript 오류 0개 확인 필수
- **PNG/폴더 저장 폐지** — `export-report-pngs.js` · `01.investus 리포트/` 저장 불필요. 사이트용은 `public/charts/*.svg`만.
- **SVG는 `*20260702*.svg`(메인)를 먼저 직접 Read해서 따라 만들고, 애매할 때만 `*20260703*.svg`(서브) 참고 — `*20260704*.svg`는 금지** / 본문에는 항상 상세 글 + 투자시사점 (스킬: `.cursor/skills/investus-report-update/`)

## 종토방(wallPosts.ts) 글 작성 규칙
- 닉네임은 `익명_XXXX` 형식으로 4자리 숫자 무작위하게 배정
- 말투는 **구어체**(반말 가능) — 공식 리포트 존댓말과 구분. 분석+개인 경험+감상 섞기
- 같은 날 같은 ticker 게시글이라도 논점/각도가 서로 달라야 한다
- holdingLabel은 "관심종목", "XX주 보유" 등 다양하게 배분

## 애널리스트(analystPosts.ts) 글 작성 규칙 — 절대 금지 패턴
- **한글판 = 한글 문장 (2026-08-27 강화).** 본문은 **한국어 존댓말 문장**으로 쓴다. `beat/AH`, `capex`, `bundle`, `unrealized`, `flight rate`, `OTA`, `ROI scenario` 같은 영문 키워드만 나열하고 끝에 `입니다`만 붙이는 글은 **반려**. 숫자는 한글 문장 속에 (`약 961억 달러`, `시간외 약 2%`). 티커·고유명사는 필요 시 한글명 병기 (`엔비디아(NVDA)`).
- **2026-08-25부터 존댓말(합니다체).** `~임`, `~이야`, `~다` 반말 금지. 구조는 다양하게, 말투만 공손하게.
- **금지**: 같은 날 같은 alias 두 번 이상 사용 금지 (예: "여의도 매 #17"을 같은 날 반복 불가)
- **금지**: 모든 글을 "~정리임", "~세트임"으로 시작하거나 끝내는 패턴 반복 금지
- **금지**: 모든 글이 "X종 세트임", "Y가지 정리" 식의 같은 구조로 시작하는 것 금지
- **⚠️ 금지 (2026-07-16 반려 사유)**: **모든 글을 "인트로 한 줄 + 1) 2) 3) 4) 5) + 투자: ~~~ + STANCE(qualifier)." 형식으로 통일하지 말 것.** 16명이 쓴 것처럼 보여야 하는데 전부 같은 틀이면 한 사람이 복붙한 것처럼 보인다. 매 세트마다 아래처럼 **구조 자체를 섞어서** 쓴다:
  - 번호 없는 자연스러운 프로즈(문단형) — 접속사로 흐름 연결, 리스트 없음
  - 짧은 대시(—) 나열형 — 숫자 1)2) 대신 "—"로 2~3개만
  - Q&A형 — "왜 민감할까요? 이유는 간단합니다 —"
  - 데이터 먼저 던지고 해석은 짧게 — "숫자만 던지고 끝" 스타일
  - 회의적/의문형 톤 — 확신 없이 "~인지 지켜봐야"로 끝내기
  - 흥분/캐주얼 톤 — 느낌표는 가능하나 **반말·음슴체 금지**, 존댓말로 온도만 높인다
  - 스탠스도 항상 "BUY(qualifier)." 대문자 태그로 끝내지 말고, 어떤 글은 "매수.", "관망.", "중립." 처럼 짧게, 어떤 글은 스탠스 태그 없이 문장 속에 자연스럽게 녹여서 끝낸다.
  - 한 세트(하루치) 안에서 위 구조가 최소 5~6가지는 섞여야 한다 — 절반 이상이 같은 구조면 반려 대상
- **금지**: 댓글도 복붙 금지. `MOCK_ANALYST_COMMENTS`에서 "OOO 숫자만으로도 포지션 점검 값이야." 류의 범용 템플릿을 티커만 바꿔 재사용하지 말 것 — 각 포스트 소재에 실제로 대응하는 구체적인 댓글을 매번 새로 쓴다.
- **다양한 오프닝 스타일** (날짜별로 섞어서 사용):
  - 채널 체크 뷰: "~쪽 채널 체크해봤는데", "~딜 플로우 확인했는데"
  - 숫자/데이터 포인트: "~보고 한 가지 숫자가 눈에 들어왔어"
  - 심층 분석: "~발언 다시 뜯어봤는데"
  - 검증: "~결과랑 딱 맞아 떨어져서"
  - 현장감: "~사진 봤는데, 속도가 예상보다"
  - 단도직입: "~가 오늘 핵심이야. 이유는..."
- 글마다 다른 관점(강세/중립/분석/의문) 배분 — 전부 강세로 쓰지 않는다
- alias는 ALIAS_POOL 전체에서 고르게 배분 (특정 alias 반복 지양)
